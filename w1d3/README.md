# w1d3 — четыре способа рассуждения

Одна задача решается четырьмя способами, N раз подряд, на одной или двух
моделях. Ответы стримятся в браузер по мере генерации, точность считается
по эталону, внизу — таблица «способ × точность × время × токены».

Задание просит сравнить, «какой способ дал наиболее точный результат».
Сравнение на глазок по одному ответу ничего не доказывает, поэтому здесь
сравнение сделано измерением:

- **эталон известен заранее** — задачи со случайными параметрами генерирует
  Rust и сам считает ответ (свежие числа не могли попасть в обучающие данные);
- **N прогонов** — модель нестабильна, и 3/3 против 0/3 — уже сравнение;
- **одинаковый хвост про формат** у всех четырёх способов
  («последней строкой `ОТВЕТ: <значение>`») — варьируется только способ
  рассуждения, всё остальное константа. Это прямой перенос дня 2: контроль
  формата делает ответ машинно-сравнимым.

## Запуск

```bash
cp ../.env.example ../.env   # вписать DEEPSEEK_API_KEY; OPENROUTER_API_KEY — для второй модели
cargo run                    # поднимает http://127.0.0.1:8787 и открывает вкладку
```

```
AI Advent · w1d3 — четыре способа рассуждения
  ✓ .env прочитан: …/ai_challenge/.env
  ✓ модель: deepseek · deepseek-v4-flash
  ✓ модель: openrouter · openai/gpt-4.1-nano
  ✓ дашборд: http://127.0.0.1:8787
```

Два режима на одной странице:

- **Бенчмарк** — тип задачи (дни между датами, день недели, подсчёт буквы в
  строке, сумма цифр произведения) или случайный; эталон считает Rust.
- **Своя задача** — любой текст плюс необязательное поле «правильный ответ».
  Есть эталон — точность считается по нему; нет — ответ слепо оценивает
  модель-судья (основная модель видит только задачу и итог, не зная, каким
  способом тот получен). В таблице источник оценки помечен: `эталон` или
  `судья`.

После эксперимента в `w1d3/REPORT.md` (рядом с `Cargo.toml`, откуда бы ни был
запущен бинарник) ложится сводка и все ответы целиком. Кнопка «Остановить»
обрывает эксперимент вместе со всеми вызовами к API; отчёт в этом случае не
пишется.

## Четыре способа

| Способ | Что уходит в модель | Вызовов |
|---|---|---|
| Прямой ответ | задача + хвост формата | 1 |
| Решай пошагово | «Решай пошагово: распиши рассуждение…» + задача | 1 |
| Мета-промпт | 1) «составь промпт для решения этой задачи»; 2) этот промпт как `system`, задача как `user` | 2 |
| Группа экспертов | аналитик, инженер, критик — три **независимых** вызова с разными `system`, друг друга не видят; потом модератор сводит их решения | 4 |

Эксперты намеренно не в одном промпте: одна модель, играющая три роли в
одном ответе, почти всегда с собой соглашается. Три отдельных контекста
расходятся по-настоящему, и модератору есть что сравнивать.

Вторая модель — нерассуждающая `openai/gpt-4.1-nano` через OpenRouter
(`SECOND_MODEL` в `.env`). Она нужна для честного ответа на вопрос
«помогает ли „решай пошагово“»: у DeepSeek V4 Flash рассуждение встроено и
работает даже в прямом режиме (видно по токенам рассуждения), так что
инструкция ему почти ничего не добавляет.

## Что получилось

Три прогона, задача «сколько полных дней между двумя датами»:

| Модель | Способ | Верно | Среднее время | Токены рассуждения |
|---|---|---|---|---|
| deepseek-v4-flash | Прямой ответ | 3/3 | 27 с | 4 125 |
| deepseek-v4-flash | Решай пошагово | 3/3 | 110 с | 15 290 |
| deepseek-v4-flash | Мета-промпт | 3/3 | 116 с | 15 701 |
| deepseek-v4-flash | Группа экспертов | 3/3 | 199 с | 51 363 |
| gpt-4.1-nano | Прямой ответ | **3/3** | 7 с | 0 |
| gpt-4.1-nano | Решай пошагово | 0/3 | 20 с | 0 |
| gpt-4.1-nano | Мета-промпт | 0/3 | 14 с | 0 |
| gpt-4.1-nano | Группа экспертов | 1/3 | 25 с | 0 |

Два прогона, «сколько раз буква встречается в строке»:

| Модель | Способ | Верно |
|---|---|---|
| deepseek-v4-flash | любой из четырёх | 2/2 |
| gpt-4.1-nano | Прямой ответ | 1/2 |
| gpt-4.1-nano | Решай пошагово | 2/2 |
| gpt-4.1-nano | Мета-промпт | 1/2 |
| gpt-4.1-nano | Группа экспертов | 0/2 |

Выводы из этих прогонов (не из общих соображений):

1. **Ответы отличаются.** На датах nano напрямую попадает три раза из трёх,
   а «пошагово» и «мета-промпт» — ноль: расписывая шаги, модель начинает
   считать дни по месяцам, ошибается на единицу или на високосный год и
   сама себя уводит от верного ответа. На подсчёте букв наоборот: пошаговая
   разметка строки помогает, прямой ответ промахивается.
2. **Для рассуждающей модели способ не важен для точности, но важен для
   цены.** DeepSeek прав всегда, но «эксперты» стоят в 12 раз больше токенов
   и в 7 раз больше времени, чем прямой ответ, за тот же результат.
3. **«Наиболее точный способ» зависит от пары модель × задача**, единого
   победителя нет. Поэтому и нужен бенчмарк с эталоном, а не один прогон.
4. **Судья без эталона ненадёжен.** В задаче «у Алисы 3 брата и 2 сестры,
   сколько сестёр у брата» слабый судья забраковал четыре верных ответа «3».
   Судьёй теперь всегда основная модель; но с эталоном лучше.

## Как устроено

```
src/main.rs     axum: `/` страница, `/run` и `/stop` эксперимента, `/events` SSE-поток
src/llm.rs      потоковый вызов Chat Completions (DeepSeek / OpenRouter), токены рассуждения отдельно
src/tasks.rs    генераторы задач с эталоном, xorshift вместо `rand`, извлечение и сравнение ответа
src/methods.rs  четыре способа и судья
static/index.html  одна страница без фреймворков: EventSource + marked для markdown
```

Эксперимент крутится в фоновой задаче tokio, все события (старт прогона,
секция карточки, токен, итог ячейки, сводка) уходят в `broadcast`-канал, а
SSE-хендлер раздаёт их браузеру. Внутри одного прогона все пары
«модель × способ» идут параллельно в `JoinSet`, эксперты внутри способа —
тоже; отмена задачи эксперимента роняет `JoinSet` и обрывает все ячейки.
Сбой судьи считается ошибкой ячейки и попадает в столбец «Ошибок», а не
маскируется под «не смог решить».

Токены встроенного рассуждения (`reasoning_content` у DeepSeek) показаны
в карточке приглушённым блоком «🧠 размышление»: он раскрыт, пока ответа
ещё нет, и сворачивается, когда ответ пошёл.

Что стоит знать перед прогоном: рассуждающая модель на датах думает долго —
режим экспертов на DeepSeek доходил до 4,5 минут и 77 тысяч токенов
рассуждения на один прогон. Для видео быстрее «подсчёт буквы» и «сумма
цифр».
