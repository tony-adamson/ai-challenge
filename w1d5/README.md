# w1d5 — слабая, средняя и сильная модель

Один и тот же запрос уходит на шесть моделей OpenRouter по N повторов на
каждую (по умолчанию 3), все запросы одновременно. Ответы стримятся в
браузер сеткой 3 × 2 (строка на тройку), внизу — сводка: время до первого токена, полное
время, токены, стоимость, скорость и доля верных ответов.

Повторы нужны потому, что одиночный замер времени ничего не значит:
латентность сети и загрузка провайдера гуляют в разы. Сравнивать можно
только средние, и только когда все шесть моделей идут в одну и ту же
минуту по одному и тому же тексту.

## Запуск

```bash
cp ../.env.example ../.env   # вписать OPENROUTER_API_KEY
cargo run                    # поднимает http://127.0.0.1:8789 и открывает вкладку
```

```
AI Advent · w1d5 — слабая / средняя / сильная модель
  ✓ .env прочитан: …/ai_challenge/.env
  ✓ слабая — qwen/qwen3.8-flash
  ✓ средняя — qwen/qwen3.8-27b
  ✓ сильная — qwen/qwen3.8-max
  ✓ слабая — google/gemma-3-12b-it
  ✓ средняя — deepseek/deepseek-v4-flash
  ✓ сильная — anthropic/claude-sonnet-5
  ✓ дашборд: http://127.0.0.1:8789
Ctrl-C — выход
```

В форме: пресет или свой запрос, эталон, число повторов. «Другая задача»
генерирует новые числа для того же пресета, «Остановить» обрывает все
запросы. После прогона дописывается `REPORT.md` рядом с `Cargo.toml`: новый
прогон встаёт сверху, старые остаются ниже (файл в `.gitignore`).

## Модели

Список берётся из `MODELS` в `.env` — id OpenRouter через запятую. По
умолчанию две тройки «слабая / средняя / сильная»:

| | Слабая | Средняя | Сильная |
|---|---|---|---|
| **Линейка одного вендора** | `qwen/qwen3.8-flash` | `qwen/qwen3.8-27b` | `qwen/qwen3.8-max` |
| **Кросс-вендорная** | `google/gemma-3-12b-it` | `deepseek/deepseek-v4-flash` | `anthropic/claude-sonnet-5` |

Одной тройки мало. Внутри линейки одного вендора всё общее — токенизатор,
данные, стиль обучения, — и разница между колонками это чистый размер
модели. Кросс-вендорная тройка отвечает на другой вопрос: держится ли
картина, когда меняется не только размер, но и вендор. Совпали обе — вывод
про классы моделей, а не про особенности одного семейства.

Подписи «слабая / средняя / сильная» ставятся по позиции в тройке: 1-я и
4-я модели — слабые, 2-я и 5-я — средние, 3-я и 6-я — сильные. Если в
`MODELS` не шесть моделей, троек нет и колонки подписываются номером.

Все шесть идут через один клиент — OpenRouter, формат OpenAI Chat
Completions со `stream: true`. Отдельные клиенты DeepSeek и Anthropic из
прошлых дней здесь не нужны: сравнение честно только тогда, когда у всех
моделей одинаковы путь запроса, сеть и способ учёта токенов.

Список можно менять через `MODELS`, борд подстроится. Оговорка одна:
`qwen/qwen3.8-max` не даёт выключить рассуждение и отвечает на такой запрос
ошибкой 400 «Reasoning is mandatory for this endpoint». Единственный случай,
когда запрос повторяется автоматически — этот: повтор уходит без поля
`reasoning`, карточка и `REPORT.md` помечаются «рассуждение обязательно», а
в колонке «Рассужд.» видно, сколько токенов на него ушло. Время, токены и
цена такого повтора с остальными впрямую несравнимы — это надо держать в
голове, читая её строку в сводке. Общих повторов при ошибках нет: 429 или
таймаут остаются ошибкой в карточке.

## Что считается

| Метрика | Как |
|---|---|
| TTFT | время от отправки запроса до первого токена ответа |
| Время | полное время вызова, до последнего токена |
| Токены in/out | `usage.prompt_tokens` / `usage.completion_tokens` из последнего чанка стрима |
| Рассуждение | `usage.completion_tokens_details.reasoning_tokens`, должно быть 0 |
| Ткн/с | `completion_tokens` ÷ полное время вызова |
| Стоимость | `usage.cost` — доллары за вызов, как их посчитал сам OpenRouter |
| Верно | ответ сошёлся с эталоном; без эталона — прочерк |

В карточке — метрики одного повтора, в сводке — средние по удачным
повторам модели; стоимость в сводке суммарная, а не средняя. Неудачный
повтор в статистику не попадает совсем: счётчики приходят последним чанком
стрима, а ошибка обрывает вызов раньше — фактический расход по ключу может
оказаться чуть выше суммы в таблице. Если у модели не вышло ни одного
повтора, в её строке прочерки, а не нули: нулями она выглядела бы самой
быстрой и бесплатной.

Сравнение с эталоном идёт не по всему ответу, а по его итогу: берётся
последняя строка с «Ответ:», иначе последняя непустая, и с неё снимается
разметка — модели любят писать `Ответ: **3**` или `$3$`. По всему тексту
сравнивать нельзя: в рассуждении «сумма 2 + 1 = 3» эталон встречается по
дороге, и неверный ответ засчитался бы верным. Дальше число сверяется с
первым числом итога (иначе «7» засчиталось бы внутри «17»), одно слово — с
точностью до окончания («в среду» подходит под «среда»). Эталон из
нескольких слов — исключение: он ищется подстрокой по всему ответу. Разбор
скопирован из w1d3 вместе с генераторами задач.

## Почему рассуждение выключено, а temperature не отправляется

**Рассуждение выключено** полем `"reasoning": {"enabled": false}` в теле
запроса. Иначе сравнение теряет смысл: у сильных моделей есть режим
размышления, у слабых его нет, и «сильная в шесть раз медленнее» окажется
измерением не модели, а режима. С выключенным рассуждением все шесть
отвечают в одном режиме — сразу текстом. Проверено прямым запросом к
`qwen/qwen3.8-flash`: в `usage` приходит `reasoning_tokens: 0`. Колонка
«Рассужд.» в сводке — контроль этого: там должны быть нули.

**`temperature` не отправляется вообще.** Sonnet 5 отклоняет это поле
ошибкой 400 (выяснено в w1d4). Выставить температуру пяти моделям и не
выставить шестой — значит сравнивать разные условия, поэтому все шесть
идут на дефолте своего провайдера. День про размер модели, а не про
температуру — её мерили вчера.

`max_tokens` — 2048. При 1024 задача про дни между датами обрывалась у трёх
моделей Qwen из шести: они считают её вслух, по месяцам, и пресет сравнивал
только оставшиеся три. Ответ, обрезанный лимитом, помечается ошибкой
«ответ оборван лимитом», а не идёт в статистику как удачный.

## Пресеты

Четыре задачи с эталоном генерирует сервер со свежими случайными
параметрами (генераторы скопированы из w1d3) — числа не могли попасть в
обучающие данные ни одной модели, и эталон считает сам Rust:

| Пресет | Что проверяет |
|---|---|
| Дни между датами | арифметику календаря без калькулятора |
| День недели по дате | ту же арифметику плюс ответ словом |
| Подсчёт буквы в строке | посимвольную работу с текстом — слабое место токенизации |
| Сумма цифр произведения | два действия подряд без рассуждения |

Пятый пресет — открытый, без эталона: «Объясни в пяти предложениях, почему
небо голубое, для десятилетнего ребёнка». Цифрой его не измерить, зато на
нём видно то, чего не видно в таблице: держит ли модель ограничение на
пять предложений, попадает ли в возраст читателя, не сбивается ли на
взрослый жаргон. Шестой пункт списка — свой запрос с необязательным
эталоном.

## Где смотреть стоимость

В карточке каждого повтора и в колонке «Стоимость» сводки — это `usage.cost`
из ответа OpenRouter, доллары за конкретный вызов. Сверить общий расход по
ключу можно на [openrouter.ai/activity](https://openrouter.ai/activity);
цены за миллион токенов по каждой модели — на её странице в каталоге
OpenRouter.

Считать «стоимость одного ответа» по прайсу вручную не нужно: OpenRouter
возвращает готовую сумму с учётом того, какой провайдер реально обслужил
запрос, — а у одной и той же модели их может быть несколько, с разными
ценами.

## Результаты и выводы

Прогоны 2026-09-04: восемь логических задач с эталоном и одна открытая, по
одному ответу на модель, рассуждение выключено везде, где модель это
позволяет. Полные ответы и цифры — в `REPORT.md`.

**Класс модели предсказывает точность хуже, чем наличие рассуждения.**

Единственная модель без промахов — Qwen 3.8 Max, и только потому, что не даёт
выключить рассуждение: 150–640 токенов раздумий перед каждым ответом. Flash и
27b из той же линейки без рассуждения ошибаются на счёте букв и дне недели.
Сильная модель без рассуждения не застрахована: Sonnet 5 насчитала сумму цифр
46 вместо 17. DeepSeek V4 Flash и Sonnet 5 дали одинаковую точность, семь из
восьми.

**Скорость различается не там, где ждёшь.**

Время до первого токена у всех нерассуждающих моделей 0.5–2 с, класс на нём не
виден. Виден на полном времени: Sonnet и DeepSeek отвечают за 2–7 с, Gemma
генерирует медленнее всех и на длинном ответе уходит за 20 с, Qwen Max ждёт до
16 с до первого токена из-за обязательного рассуждения. Длина ответа важнее
класса: «ответ — одно число» соблюдают Gemma, DeepSeek и Sonnet, Qwen Flash и
27b пишут сотни токенов решения. При этом Flash, отвечая мгновенно одним
токеном, промахивается, а расписав решение — попадает.

**Цена за ответ различается в 50–100 раз при близкой точности.**

Gemma 12b — самая дешёвая, Sonnet 5 — самая дорогая. DeepSeek V4 Flash по цене
слабая модель, по точности сильная: в 20–50 раз дешевле Sonnet 5 при том же
результате. Qwen Max дорог не тарифом, а рассуждением, которое нельзя
отключить.

**Общий вывод.** На задачах такого уровня платить за сильную модель без
рассуждения смысла мало: DeepSeek Flash даёт ту же точность на порядок
дешевле. Сильная модель окупается, когда нужен короткий точный ответ с первого
раза без рассуждения; слабая — когда цена важнее одного промаха из семи.

### Оговорки

- По одному ответу на задачу: разброс между повторами не измерялся, один
  промах — в пределах шума.
- Первый прогон шёл со сломанной проверкой ответа («Ответ: 3» считался
  неверным), результаты сверены вручную.
- Три модели Qwen на задаче про дни между датами упёрлись в лимит 1024 токена;
  после этого лимит поднят до 2048.
