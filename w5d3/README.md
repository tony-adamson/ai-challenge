# w5d3 — query rewrite и фильтрация RAG

День 23: после поиска по косинусу появляется второй этап — отсечение по
similarity. Переписывание вопроса через текущую LLM включается отдельно.
Это фильтр, **не reranker**: порядок кандидатов не меняется.

## Запуск

Rust 1.88 или новее. Команды — из `w5d3/`. Ключи и провайдер — в корневом
`.env`, как в дне 22. По умолчанию DeepSeek `deepseek-v4-flash`;
`LLM_MODEL` переопределяет модель. День самостоятелен по коду и сборке,
но читает готовые данные дня 21: `../w5d1/index.db` и кэш
`../w5d1/.fastembed_cache` (или `HF_HOME`). Если их нет, сначала выполни
`cargo run --release -- index` из `w5d1/`. Этот день индекс не изменяет.

```bash
cargo run --release -- ask "Где узнать, сколько долларов стоил конкретный вызов модели?" --mode baseline
cargo run --release -- ask "Где узнать, сколько долларов стоил конкретный вызов модели?" --mode filter
cargo run --release -- ask "Какой PIN-код у моей банковской карты?" --mode full
cargo run --release -- compare
```

Флаги:

| Флаг | По умолчанию | Значение |
| --- | --- | --- |
| `--before N` | 10 | сколько ближайших чанков взять из поиска |
| `--after N` | 3 | максимум чанков в контексте после второго этапа |
| `--threshold X` | 0.85 | оставить `similarity >= X`, диапазон −1…1 |
| `--mode NAME` | `full` | режим команды `ask` |
| `--index PATH` | индекс дня 21 | другой совместимый индекс |
| `--retrieval-only` | выключен | без rewrite и генерации, ключ не нужен |

Нужно `0 < after <= before`. `--help` показывает команды. Книжного режима нет.
`--retrieval-only` с `ask` требует `--mode baseline` или `filter`;
с `compare` сравнивает только эти два режима. `compare` всегда сравнивает
все доступные режимы, `--mode` на него не влияет.

```bash
cargo run --release -- calibrate
cargo run --release -- compare --retrieval-only
cargo run --release -- ask "Какой PIN-код у моей банковской карты?" --mode filter --retrieval-only --before 10 --after 3 --threshold 0.85
```

## Пайплайн и режимы

| Режим | Поисковый запрос | Отбор контекста |
| --- | --- | --- |
| `baseline` | исходный вопрос | первые `after` из `before`, без порога |
| `filter` | исходный вопрос | порог, затем максимум `after` |
| `rewrite` | одна короткая строка от LLM | без порога |
| `full` | та же строка rewrite | порог, затем максимум `after` |

Эмбеддинги — локальный `multilingual-e5-small`, стратегия `structure`.
Поиск использует `query: ` и нормализованный вектор, как дни 21–22.
Rewrite сохраняет смысл и не должен добавлять факты; это инструкция модели,
а не гарантия. Многострочный, пустой или слишком длинный ответ — ошибка.
Ошибки API не маскируются возвратом к другому режиму; таймаут запроса — 120 с.

Для **генерации ответа всегда используется исходный вопрос**. Найденные
фрагменты помечены как данные, не инструкции. Если отбор пуст — программа
возвращает фиксированный отказ без вызова генератора. Это не доказательство,
что ответа нет во всём корпусе. Каждый кандидат печатается с оценкой и причиной:
«в контекст», «отсечён порогом», «за пределами after».

В `compare` rewrite вызывается один раз на вопрос и переиспользуется в двух
режимах. Кандидаты baseline/filter тоже одинаковы. Ответы генерируются отдельно,
поэтому различия при одинаковом контексте могут быть случайностью LLM.
Полный прогон — максимум 75 API-вызовов: 15 rewrite + 60 генераций;
пустой контекст сокращает число генераций.

## Порог и контрольные вопросы

`calibrate` — отдельные четыре вопроса: настройка TOTP, поля `save_to_file`,
гарантия холодильника и масса Европы. Они не входят в контрольный `compare`.
У известных релевантных чанков исходных вопросов оценки 0.891 и 0.866;
максимумы на двух вопросах без ответа — 0.803 и 0.773. Выбран порог 0.85:
он между этими группами. Это маленькая калибровочная выборка, не универсальный
порог и не проверка распределения оценок после rewrite.

`compare` использует 10 вопросов дня 22, три разговорные переформулировки
(хвост переписки, перезапуск сервера, проверка ответа) и два вопроса без ответа
(дозировка лекарства и PIN). В коде `QUESTIONS`/`EXTRA` заранее записаны
ожидания, файл и раздел. Автоматические метрики: попадание файла и раздела,
пустой контекст на отрицательных вопросах, среднее число чанков.
Правильность ответа оценивается вручную по ожиданию, не по наличию источника.

## Живое сравнение

Прогон 2026-09-30: DeepSeek `deepseek-v4-flash`, `before=10`, `after=3`,
`threshold=0.85`. Порог не менялся по результатам контрольного прогона.

| Режим | Файл / 13 | Файл+раздел / 13 | Пустой контекст / 2 | Среднее чанков |
| --- | --- | --- | --- | --- |
| baseline | 12 | 9 | 0 | 3.00 |
| filter | 12 | 9 | 2 | 2.00 |
| rewrite | 13 | 9 | 0 | 3.00 |
| full | 12 | 8 | 2 | 2.47 |

По текстам ответов:

- Вопрос 6 про валидатор: baseline/filter нашли раздел «Ограничения» и не
  объяснили механизм. Rewrite/full нашли «Двойную защиту» и описали отдельный
  вызов с JSON нарушений — улучшение относительно ожидания.
- Вопрос 9 про доллары: baseline/filter указали `usage.cost` и карточку повтора;
  rewrite/full ушли к стоимости всего чата и отказались отвечать — ухудшение.
- Вопрос 12 про выключенный сервер: rewrite ответил про сохранение паузы,
  но full отрезал нужный чанк с оценкой **0.846** и отказался — ложное отсечение.
- На двух вопросах без ответа все режимы отказались: baseline/rewrite благодаря
  инструкции генератору, filter/full без генерации и без нерелевантных источников.

Вывод: фильтр исходного запроса сократил контекст на треть без потери попаданий
в этом прогоне. Rewrite помогает не всегда; тот же порог после rewrite потерял
полезный чанк. **Улучшение общей точности ответов не доказано.** Даже попадание
файла не гарантирует правильный раздел, а генератор иногда отказывает, имея факт.
Повторный прогон может дать другие rewrite и ответы.

## Проверки и видео

```bash
cargo test
cargo clippy --all-targets -- -D warnings
cargo build --release
```

Тесты: граница порога, K и порядок, инварианты на сгенерированных оценках,
rewrite и генерация через локальный HTTP-mock, ошибки API/формата rewrite,
отсутствие вызова генератора при пустом контексте, некорректные CLI-параметры.

Для видео: покажи `select`, `REWRITE_SYSTEM`, исходный/поисковый запрос;
сравни baseline/filter на стоимости вызова и PIN, затем запусти `compare`.
Покажи итоговую таблицу, улучшение на валидаторе и потерю чанка после rewrite.
Не показывай `.env`. Видео и публикация кода — отдельные шаги сдачи.
