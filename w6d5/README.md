# День 30: локальная LLM как приватный сервис

Qwen3.5-9B (4-bit, MLX) работает на домашнем Mac и доступна из интернета по HTTPS с телефона:
чат и OpenAI-совместимый API по общему токену, с очередью и лимитами.

```
телефон → https://challenge.hoapps.dev/llm/ (Caddy на VPS, срезает /llm)
        → ssh -R туннель → шлюз w6d5 на Mac 127.0.0.1:8090 → mlx_lm.server 127.0.0.1:8080
```

Модель не покидает Mac; наружу смотрит только шлюз, и только через туннель (оба порта слушают 127.0.0.1).

## Что делает шлюз (`src/main.rs`, axum)

| Путь | Токен | Что |
|:--|:--|:--|
| `GET /` | нет | чат (`chat.html`, вшит в бинарник) |
| `GET /health` | нет | `mlx` — модель отвечает, `busy` — идёт генерация, `queued` — ждут в очереди, лимиты |
| `POST /v1/chat/completions` | `Authorization: Bearer <LLM_TOKEN>` | прокси в mlx_lm.server, формат OpenAI |

Ограничения (константы в начале `main.rs`):

| Что | Лимит | Ответ |
|:--|:--|:--|
| Нет/неверный токен | один общий `LLM_TOKEN` | 401 |
| Частота | 6 запросов в минуту с IP (IP — первый элемент `X-Forwarded-For` от Caddy, иначе адрес сокета) | 429 + `Retry-After` |
| Контекст | 16 000 символов суммарно по `messages` | 413 |
| Параллельность | 1 генерация, ещё 3 ждут в очереди | лишние — 503 + `Retry-After` |
| Длина ответа | `max_tokens` зажимается в 1…512 (нет — 512) | — |
| `stream: true` | не поддерживается: ответ целиком, так проще держать очередь | 400 |

В каждый запрос шлюз добавляет `enable_thinking: false` (размышления Qwen выключены) и сэмплинг
temp 0.7 / top_p 0.8 / top_k 20, если клиент не задал свой. В mlx уходят только `messages`, `temperature`,
`top_p`, `top_k`, `stop`, `seed`: остальное (`model`, `adapters`, `draft_model` — пути к весам, которые mlx
грузит сам) шлюз отбрасывает, отвечает загруженная модель.
Лимит частоты проверяется первым: в него считается каждый запрос, в том числе с неверным токеном
(перебор токена тоже упирается в 6 в минуту) и получивший 503/413.

## Запуск

Нужны веса и окружение из `../w6d1` (README w6d1) и строка `LLM_TOKEN=<секрет>` в корневом `.env`.

```sh
sh scripts/serve.sh    # mlx_lm.server + шлюз; Ctrl+C — остановить оба
sh scripts/tunnel.sh   # во втором терминале: открыть доступ через VPS
```

Без `LLM_TOKEN` шлюз не стартует. Если 8080 или 8090 заняты — скрипт говорит, кем, и выходит, чужое не трогает.
Туннель живёт, пока открыт терминал: закрыл — сервис снаружи недоступен (автозапуска нет намеренно).

Телефон: открыть `https://challenge.hoapps.dev/llm/`, один раз ввести токен (хранится в браузере; кнопка «Токен» — сменить).

## Проверка

```sh
cargo test                                         # шлюз против mock mlx: 401, 413, 429, 503, очередь по одному, прокси
sh scripts/load.sh 6                               # 6 параллельных запросов локально (токен из .env)
sh scripts/load.sh 6 https://challenge.hoapps.dev/llm   # то же через интернет
curl https://challenge.hoapps.dev/llm/v1/chat/completions -H "Authorization: Bearer $LLM_TOKEN" \
  -H 'Content-Type: application/json' -d '{"messages":[{"role":"user","content":"Привет"}]}'
```

Прогон `load.sh 6` на M2 / 16 GB: 4 запроса — 200 за 3, 6, 10, 15 с (выполняются по одному, остальные ждут),
2 — сразу 503 (очередь полна); `/health` во время прогона — `busy: true, queued: 3`. Повторный запуск в ту же
минуту — все 429. После нагрузки модель отвечает как обычно.
