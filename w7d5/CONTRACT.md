# Контракт интеграции: чат поддержки Эми в личном кабинете

Документ для фронтенда и бэкенда сервиса, в который встраивается виджет. Эми — отдельный сервис:
виджет говорит только с ней, а Эми сама спрашивает у бэкенда кабинета, кто пишет.

```
браузер (кабинет) ──token──▶ Эми: POST {api}/api/widget/chat ──token──▶ бэкенд кабинета: GET {CUSTOMER_API}/v1/customer
```

## 1. Фронтенд: как встроить виджет

```html
<script src="https://<адрес Эми>/emi-widget.js"></script>
<emi-support token="<токен сессии кабинета>" api="https://<адрес Эми>/"></emi-support>
```

| Атрибут | Обязателен | Что это |
|---|---|---|
| `token` | да | Токен текущей сессии личного кабинета — тот же, с которым фронт ходит в API кабинета. Эми передаст его бэкенду в `Authorization: Bearer`. |
| `api` | нет | Базовый URL Эми. По умолчанию `./` — относительно страницы. |

- Веб-компонент со своим Shadow DOM: стили страницы на него не влияют. Цвет — CSS-переменная `--emi-accent`
  на странице (наследуется внутрь).
- Методы элемента: `open()`, `close()` — например, для своей кнопки «Нужна помощь?».
- В React: тег как обычный DOM-элемент (`<emi-support token={token} />`), скрипт подключается один раз.
  Смена пользователя — удалить элемент и создать новый: история чата живёт в элементе.
- Токен можно обновлять атрибутом: виджет читает его на каждом сообщении.
- Запросы виджета идут на `{api}/api/widget/chat`. Если Эми на другом origin, чем кабинет, нужен CORS
  на стороне Эми или проксирование её под путь кабинета (например, `/support/`) — в текущей версии
  CORS не включён, проще проксировать.

## 2. Бэкенд: что должен отдавать API «токен → клиент»

Эми настраивается переменной `CUSTOMER_API` (базовый URL) и вызывает:

```
GET {CUSTOMER_API}/v1/customer
Authorization: Bearer <токен сессии кабинета>
```

Таймаут — 5 с (соединение — 3 с). Токен Эми не хранит и не пишет в логи.

### Ответ 200 — JSON

```json
{
  "id": "c-101",
  "name": "Ирина Соколова",
  "email": "irina.sokolova@example.com",
  "brand": {"id": "vetrilo", "name": "Ветрило"},
  "plan": {"name": "Месяц", "price": "299 ₽ в месяц"},
  "subscription": {"status": "expired", "until": "2026-10-12", "autorenew": false},
  "trial_used": true,
  "payments": [
    {"date": "2026-09-12", "amount": "299 ₽", "status": "succeeded", "method": "карта *4417"},
    {"date": "2026-10-12", "amount": "299 ₽", "status": "failed", "method": "карта *4417", "note": "недостаточно средств"}
  ],
  "server_countries": ["Финляндия", "Нидерланды", "Германия"]
}
```

| Поле | Тип | Смысл |
|---|---|---|
| `id` | string, **обязателен, непустой** | Стабильный id клиента. К нему Эми привязывает обращения, историю чата и лимиты. Нет `id` — ответ считается ошибкой. |
| `name`, `email` | string | Как обращаться и куда придёт ответ специалиста. |
| `brand` | `{id, name}` | Витрина/бренд, через который клиент пришёл. Эми называет сервис по `brand.name`. |
| `plan` | `{name, price}` или `null` | Текущий тариф; `null` — тариф не выбран (например, был только пробный период). |
| `subscription.status` | `active` \| `trial` \| `expired` | Другое значение покажется модели как есть. |
| `subscription.until` | string `YYYY-MM-DD` | Дата окончания (или когда закончилась). |
| `subscription.autorenew` | bool | Включён ли автоплатёж. |
| `trial_used` | bool | Пробный период уже использован. |
| `payments[]` | массив, от старых к новым | Эми видит последние 3. `status`: `succeeded` \| `pending` \| `failed` \| `refunded`; `note` — необязательное пояснение. |
| `server_countries` | string[] | Страны, доступные клиенту. |

Даты и суммы — строками, как их увидит клиент: Эми цитирует их дословно.

### Ошибки

| Код | Что сделает Эми |
|---|---|
| `401` / `403` | Токен не узнан → виджету `401 «Сессия кабинета не найдена — войдите заново»`, модель не вызывается. |
| другой не-2xx, таймаут, не JSON, нет `id` | Виджету `503 «Не удалось получить данные кабинета»`, причина — в лог Эми (без токена). |

## 3. API Эми для виджета

```
POST {api}/api/widget/chat
Authorization: Bearer <токен кабинета>
Content-Type: application/json

{"text": "Почему не работает VPN?"}
```

Любые id клиента в теле игнорируются: клиент определяется только по ответу `CUSTOMER_API`.

Ответ `200`:

```json
{"kind": "answer", "known": true, "answer": "…",
 "quotes": [{"label": "Личный кабинет · профиль", "text": "Подписка: истекла 2026-10-12, автоплатёж выключен"}],
 "handed": ["Создан тикет T-1012 «…», статус: ждёт специалиста."]}
```

- `quotes` — дословные цитаты из базы знаний и данных клиента, их проверяет код Эми; `label` — источник.
- `handed` — непустой, если в этом ответе вопрос передан специалисту (создано или дополнено обращение).
- `kind: "error"` + `text` — понятная ошибка (в т.ч. при `200`, если модель не дала проверяемого ответа).
- Служебные поля (`providers`, `tools`, `fallback`, `retried`) — для отладки, виджет их не показывает.

Ошибки до модели: `401` (нет токена / токен не узнан), `400` (пустое сообщение или длиннее 1000 символов),
`429` (лимит), `503` (бэкенд кабинета недоступен). Тело — `{"kind": "error", "text": "…"}`.

## 4. Что Эми хранит и чего не хранит

| Хранит | Где | Сколько |
|---|---|---|
| Обращения к специалисту (тема, сводка, id клиента) | CRM Эми (`crm.json`) | постоянно |
| Последние 10 сообщений чата на клиента | память процесса | до перезапуска |
| Счётчики лимитов по `id` | память процесса | до перезапуска |

Не хранит: токены кабинета, ответы `CUSTOMER_API` (запрашиваются заново на каждое сообщение), пароли,
платёжные данные сверх того, что вернул кабинет и что модель записала в сводку обращения.
Модель видит данные только того клиента, чей токен пришёл; инструменты CRM привязаны к его `id` кодом.

## 5. Лимиты

- Сообщение — не длиннее 1000 символов.
- 20 сообщений в час на клиента (скользящее окно, по `id` из `CUSTOMER_API`).
- 300 сообщений в сутки на всех (скользящее окно) — защита бюджета LLM.

При превышении — `429` и текст с тем, когда можно написать снова.

Лимиты считаются после проверки токена: каждое сообщение виджета, в том числе с выдуманным токеном, — один запрос к `CUSTOMER_API`. С настоящим бэкендом ограничьте частоту запросов к `api/widget/chat` по IP на прокси.
