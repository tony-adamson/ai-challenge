# w5d4 — RAG с источниками, цитатами и режимом «не знаю»

День 24: ответ RAG обязан содержать сам ответ, список источников
(`source · section · chunk_id`) и дословные цитаты из найденных чанков.
Если релевантность ниже порога или во фрагментах нет ответа — ассистент
говорит «не знаю» и просит уточнить вопрос.

## Запуск

Rust 1.88 или новее. Команды — из `w5d4/`. Ключи и провайдер — в корневом
`.env`, как в прошлые дни; по умолчанию DeepSeek `deepseek-v4-flash`,
`LLM_MODEL` переопределяет модель. День читает готовые данные дня 21:
`../w5d1/index.db` и кэш `../w5d1/.fastembed_cache` (или `HF_HOME`).
Если их нет — сначала `cargo run --release -- index` в `w5d1/`. Индекс не меняется.

```bash
cargo run --release -- ask "Где узнать, сколько долларов стоил конкретный вызов модели?"
cargo run --release -- ask "Какой PIN-код у моей банковской карты?"
cargo run --release -- check
cargo run --release -- calibrate
```

| Флаг | По умолчанию | Значение |
| --- | --- | --- |
| `--before N` | 10 | сколько ближайших чанков взять из поиска |
| `--after N` | 3 | максимум чанков в контексте после порога |
| `--threshold X` | 0.85 | оставить `similarity >= X`, диапазон −1…1 |
| `--index PATH` | индекс дня 21 | другой совместимый индекс |
| `--retrieval-only` | выключен | без LLM: кандидаты и решение шлюза, ключ не нужен |

Нужно `0 < after <= before`. Rewrite и `--mode` из дня 23 убраны: поиск идёт
по исходному вопросу, порог применяется всегда.

## Пайплайн

1. **Шлюз порога.** Поиск по `multilingual-e5-small`, затем отбор
   `score >= threshold`, максимум `after`. Отбор пуст — детерминированное
   «не знаю» **без вызова LLM**: лучший score, просьба уточнить и до трёх
   ближайших разделов как подсказка «возможно, ты про…».
2. **JSON-ответ.** Фрагменты нумеруются `[1]..[n]` и помечены как данные,
   не инструкции. Вызов идёт с `response_format: {"type":"json_object"}`.
3. **Проверка кодом.** При `known: true`: `answer` непуст, `quotes` непуст,
   `chunk` в `1..=n`, цитата после схлопывания пробелов не короче 20 символов
   и является подстрокой так же нормализованного чанка с этим номером.
   При `known: false` — «не знаю» с теми же подсказками разделов.
4. **Повтор.** Проверка не прошла — ровно один повторный вызов с текстом
   ошибки. Второй провал — честный отказ «не удалось получить ответ с
   проверяемыми цитатами». Ошибки HTTP/API не маскируются.
5. **Источники** собирает код по номерам принятых цитат; модель их не пишет.
6. **Судья.** Отдельный JSON-вызов: вопрос, ответ, цитаты →
   `{"reason": "...", "supported": bool}` — сначала рассуждение, потом вердикт.
   Ответ-отказ («во фрагментах нет») или ответ не на заданный вопрос —
   `supported: false`. Судья ответ не меняет; невалидный JSON судьи —
   вердикт «не определён».

Формат ответа модели:

```json
{"known": true, "answer": "...", "quotes": [{"chunk": 1, "text": "дословный кусок фрагмента [1]"}]}
```

## Живой прогон `check`

Прогон 2026-10-02: DeepSeek `deepseek-v4-flash`, `before=10`, `after=3`,
`threshold=0.85`. API принял `response_format: json_object`. Порог не менялся
по результатам. 10 контрольных вопросов дня 22 + 2 без ответа (дозировка
лекарства, PIN). 20 вызовов API: 10 ответов + 10 судей, повторов не было.

| Метрика | Результат |
| --- | --- |
| источники есть | 10/10 отвеченных |
| цитаты есть (дословность проверена кодом) | 10/10 отвеченных |
| судья «подтверждено» | 9/10 отвеченных (вопрос 6 — «не подтверждено») |
| «не знаю» на вопросах без ответа | 2/2 (оба — шлюз порога, LLM не вызывалась) |
| ложные «не знаю» / провалы проверки на 10 положительных | 0 / 0 |
| вопросов с повтором | 0 |

Ручная сверка с ожиданиями из `QUESTIONS`:

- Совпадают по смыслу: 1, 3, 4, 7, 8, 9, 10.
- Вопрос 2: ответ не по вопросу. Модель взяла из лекции причины, почему
  stateless-агент ошибается (нет профиля, state machine, инвариантов), и
  выдала их за вред отправки всего сразу. Цитаты дословны, судья поставил
  «подтверждено» — новое правило «не отвечает на вопрос» этого не поймало.
- Вопрос 5: ответ частичный — про размер хвоста `keep_last`, без «системный
  промпт + последние N сообщений». Судья: «подтверждено».
- Вопрос 6: поиск дал раздел «Ограничения» вместо «Двойной защиты»; ответ
  не про механизм проверки. Судья: «не подтверждено» (по формальной причине:
  утверждение «ответ проверяет валидатор» не следует из цитат).

Прошлый прогон 2026-10-01 со старым промптом судьи: «подтверждено» 10/10,
1 повтор (вопрос 4). На вопросе 2 модель тогда вернула `known: true` с
текстом «во фрагментах нет ответа», и судья засчитал этот отказ. В прогоне
2026-10-02 модель на вопросе 2 отказом не ответила, поэтому новое правило
судьи на ответе-отказе вживую не проверено.

Отдельный `ask` про стоимость вызова 2026-10-01: судья вернул
«не подтверждено» — ответ добавил `openrouter.ai/activity`, которого нет
в цитатах. Проверка кода ловит недословные цитаты, а утверждение без цитаты
ловит только судья.

## Ограничения

- Дословная цитата доказывает, что фрагмент существует, но не что ответ
  правильный и что каждое утверждение ответа опирается на цитату.
- Судья — та же модель и пропускает ответы не по вопросу (вопрос 2,
  2026-10-02), а частичные ответы считает подтверждёнными (вопрос 5).
- Промпт судьи изменён после первого прогона 2026-10-01 по его результатам
  (тогда «подтверждено» 10/10, включая ответ-отказ на вопросе 2): добавлены
  `reason` перед `supported` и правило про отказ. Это правка по контрольному
  набору, отдельной выборки для проверки судьи нет.
- `known: true` с ответом «во фрагментах нет» код не распознаёт.
- Порог 0.85 откалиброван в дне 23 на маленькой выборке (`calibrate`);
  это не универсальная граница. Подсказки разделов берутся из кандидатов
  ниже порога и могут быть нерелевантны.

## Проверки и видео

```bash
cargo test
cargo clippy --all-targets -- -D warnings
cargo build --release
```

Тесты через локальный HTTP-mock: граница порога и инварианты отбора;
принятый JSON и сбор источников кодом; цитата с другими пробелами; чужая,
короткая, с многоточием цитата, номер вне диапазона, пустые quotes;
повтор, который исправляет ответ, и повтор с итоговым отказом; пустой отбор
без вызова LLM с подсказками; `known: false`; вердикт судьи и невалидный
JSON судьи; ошибки API; некорректные CLI-параметры и отсутствие `--mode`.

Для видео: покажи `ANSWER_SYSTEM`, `parse_reply` и сбор источников в
`answer`; запусти `ask` про стоимость вызова (ответ, источники, цитаты,
судья) и `ask` про PIN («не знаю» с подсказками), затем `check` и сводку.
Не показывай `.env`.
