# День 33: поддержка пользователей VPN

Мини-сервис поддержки для вымышленного VPN-сервиса «Ветрило». Всё — симуляция: бренд, тарифы, клиенты,
платежи и тикеты синтетические, e-mail вида `@example.com`, сервис работает только на localhost.

Окно во вкладке браузера: слева выбор клиента (имитация «кто залогинен») и его карточка из CRM — тариф,
подписка, устройства, платежи, тикеты. Справа чат этого клиента с ассистентом Эми. Эми:

- **отвечает по FAQ через RAG** — `data/faq/*.md` (подключение, тарифы, оплата и возвраты, устройства,
  скорость, диагностика, когда подключается специалист). Индекс пересобирается при каждом старте и лежит
  во временной папке, модель эмбеддингов — общий кэш `~/.cache/emi/`. Файл `specialist.md` (сроки ответа,
  тикеты, конфиденциальность) в источниках всегда: в поиске по «деньги списали» он проигрывает разделу про платежи;
- **учитывает данные клиента из CRM через MCP** — тот же бинарник дочерним процессом (`emi mcp-crm --data <dir>`)
  поднимает stdio MCP-сервер над `data/crm.json` с тулами `get_profile`, `list_tickets`, `create_ticket`,
  `add_ticket_message`. Профиль и тикеты хост берёт перед каждым вопросом сам (на них же строится карточка),
  писать в CRM модель может только тулами;
- **не может решить — передаёт специалисту**: создаёт тикет или дописывает уже открытый по той же теме,
  статус `waiting_human` («ждёт специалиста»), и честно говорит об этом. Закрыть или решить тикет нельзя —
  такого тула нет. Карточка слева перечитывается после каждого ответа;
- **цитаты проверяет код** — как в `/help`: каждая цитата дословно есть в своём источнике (фрагмент FAQ или
  результат тула CRM), одна попытка исправить, затем честная ошибка вместо непроверенного ответа. Под ответом —
  источники `faq/файл · секция` и `CRM · get_profile`, какая модель ответила, fallback, вызванные MCP-тулы.

Чужие данные модель получить не может: в схемах тулов нет `user_id`, его подставляет хост — клиента,
выбранного в окне, поверх любых аргументов модели. Сервер CRM отдаёт и меняет только тикеты этого клиента;
чужой и несуществующий тикет дают одну и ту же ошибку.

История чата — в памяти процесса, своя у каждого клиента, последние 10 сообщений, до перезапуска.
Постоянный контекст — тикеты.

## Запуск

```bash
cd w7d3
cargo run --release -- support            # данные из ./data; другая папка — --data <dir>
```

Печатает ссылку `http://127.0.0.1:8765/?t=<токен>`; без токена — 403. Ключи — `GEMINI_API_KEY` и/или
`DEEPSEEK_API_KEY` в `.env` в корне репозитория (Gemini Flash, при ошибке — DeepSeek).

При первом старте `data/crm.json` создаётся из `data/crm.seed.json` и дальше меняется ассистентом.
**Сброс демо** — остановить Эми и удалить `data/crm.json`.

# День 32: Эми — ревью PR в GitHub Actions

Копия дня 31 (окно с `/help`, описано ниже) плюс подкоманда `emi review`: ассистент получает diff PR,
подтягивает правила проекта и соседний код через RAG и пишет ревью — потенциальные баги, архитектурные
проблемы, рекомендации. GitHub Action (`.github/workflows/emi-review.yml`) запускает её на каждом PR
и оставляет один комментарий «Эми: ревью».

## Ревью PR (`emi review`)

```bash
cd w7d2
cargo run --release -- review --repo ~/MyProjects/ai_challenge --base main [--head <ref>]
```

Markdown ревью — в stdout, ход работы — в stderr. `--head` по умолчанию `HEAD`.

1. **Diff.** `git diff <base>...<head>` (`--no-optional-locks`, stdin `/dev/null`) и список файлов
   (`--name-status`). Lock-файлы в содержимое не идут. Diff больше 60 КБ обрезается — в ревью пометка.
   Модель видит diff с номерами строк новой версии.
2. **RAG «доки + код».** Свежий индекс в отдельной БД `<git-common-dir>/emi/review.db` (индекс окна
   не трогается): все tracked `*.md` + `Cargo.toml`/`package.json` репозитория и код (`*.rs`, `*.py`,
   `*.js`, `*.ts`, `*.yml`) только из папок верхнего уровня, которые трогает PR. Поиск по каждому ханку,
   до 6 фрагментов доков и до 6 фрагментов кода — раздельные квоты, иначе код всегда ближе к ханку, чем правила.
   Корневые `CLAUDE.md`/`AGENTS.md` идут в источники целиком всегда: правила по смыслу далеки от кода
   и в поиске проигрывают README (на демо-PR без этого терялось правило «без общих модулей»).
3. **LLM** (Gemini → DeepSeek) за один запрос возвращает JSON с находками
   `{kind, file, line, title, detail, source?, quote?}`. Неразборчивый JSON — одна попытка исправить.
4. **Проверка кодом** (`review::verify_findings`): файл есть в PR; строка — добавленная или контекстная
   строка новой версии в ханках diff (`recommendation` может быть без строки — совет про файл целиком);
   цитата дословно есть в источнике N (та же нормализация, что в `/help`). Не прошедшие находки
   отсеиваются, в ревью — «Отсеяно непроверенных находок: N» с причинами.
5. **Markdown**: заголовок, модель/fallback, три раздела, у находки `` `файл:строка` ``, у правила —
   цитата и `файл · секция`. Пустой раздел — «не найдено».

### GitHub Action

На `pull_request` (opened, synchronize, reopened), права `contents: read`, `pull-requests: write`.
PR из форков пропускаются: секретов у них нет. Шаги: checkout с полной историей → Rust stable →
кэш cargo/target и модели эмбеддингов (`~/.cache/emi`) → `cargo build --release` →
`emi review --base origin/<base> --head <sha PR>` → Job Summary + комментарий
(свой комментарий ищется по скрытому маркеру и обновляется, нет — создаётся новый). Упало ревью — в комментарии
«ревью не выполнено», job красный: старое ревью не остаётся висеть как актуальное.

Нужны секреты репозитория `GEMINI_API_KEY` и/или `DEEPSEEK_API_KEY` (Settings → Secrets → Actions).
`.env` в CI нет — ключи берутся из переменных окружения.

# День 31: Эми — ассистент разработчика (`/help` по докам и git)

Эми — локальный ассистент для одного разработчика. Запускается на репозитории, открывает окно
во вкладке браузера: слева карточка проекта (имя, ветка, статус, последние коммиты), справа чат.

`/help <вопрос>` отвечает по документации проекта и, если вопрос про состояние репозитория, по git:

- **RAG по докам.** Индексируются все tracked `*.md` плюс `Cargo.toml`/`package.json` (`git ls-files`).
  Разбиение по разделам markdown (из w5d1), эмбеддинги multilingual-e5-small (fastembed), SQLite, косинус.
  Папка, прямо названная в вопросе («как запустить w6d5?»), поднимается в выдаче.
- **Git через MCP.** Тот же бинарник запускается дочерним процессом как stdio MCP-сервер
  (`emi mcp-git --repo <path>`) с read-only тулами `git_branch`, `git_status`, `git_log`, `git_diff`,
  `list_files`. Модель вызывает их через tool calling. Git запускается с `--no-optional-locks`,
  stdin — `/dev/null`, пути-аргументы не могут быть флагами или выходить из репозитория.
- **Проверенные цитаты.** Модель возвращает JSON с ответом и цитатами `{source: N, text}`.
  Код проверяет, что каждая цитата дословно есть в источнике N (фрагмент дока или результат
  git-тула). Не прошло — одна попытка исправить, потом честная ошибка вместо непроверенного ответа.
  Файл и раздел (`файл · секция`) подставляет код по номеру источника.
- **Нет в доках — так и говорит**, с подсказкой ближайших разделов.

Мозг — Gemini Flash (`gemini-3.8-flash`) через OpenAI-совместимый эндпоинт Google. Ошибка Gemini
(сеть, HTTP, пустой ответ) → тот же запрос уходит в DeepSeek (`deepseek-v4-flash`). В чате видно,
какая модель ответила и почему сработал fallback.

## Запуск

Ключи — в `.env` в корне репозитория: `GEMINI_API_KEY`, `DEEPSEEK_API_KEY` (достаточно одного).

```bash
cd w7d2
cargo run --release -- --repo ~/MyProjects/ai_challenge
```

Печатает ссылку `http://127.0.0.1:8765/?t=<токен>` — открыть в браузере. Токен новый на каждый
запуск; запрос без него (`?t=` или заголовок `x-emi-token`) получает 403. Без `--repo` — текущая папка.
Второй экземпляр на том же порту не стартует и говорит об этом.

Первый запуск качает модель эмбеддингов (~480 МБ на диске) в `~/.cache/emi/` и собирает индекс
(~1 мин на этом репозитории). Индекс лежит в `<git-common-dir>/emi/index.db` (для обычного
репозитория — `.git/emi/`), в рабочее дерево ничего не пишется.

## Команды чата

| Команда | Что делает |
|---|---|
| `/help <вопрос>` | ответ по докам и git с цитатами `файл · секция` |
| `/help` | список команд |
| `/reindex` | пересобрать индекс (после правки документации) |

Примеры: `/help как запустить w6d5?`, `/help какой провайдер LLM по умолчанию?`,
`/help на какой ветке репо и последние коммиты?`.

## Проверка fallback

```bash
GEMINI_API_KEY=broken cargo run --release -- --repo ~/MyProjects/ai_challenge
```

Переменная окружения сильнее `.env`: Gemini отвечает 400, ответ даёт DeepSeek, в чате — плашка
`fallback: gemini: HTTP 400 …`.

## Тесты

```bash
cargo test
cargo clippy --all-targets -- -D warnings
```

Чанкинг (`rag::chunk`), проверка цитат (`help::verify_quotes`: выдуманная цитата отклоняется,

## Ограничения

- История чата не сохраняется между запусками; ответ приходит целиком, без стриминга.
- Индекс не обновляется сам — после правки доков нужен `/reindex`.
- Один проект на запуск; переключение — перезапуском с другим `--repo`.
