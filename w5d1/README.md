# w5d1 — индексация документов

День 21: CLI режет Markdown-документы репозитория на чанки двумя стратегиями,
считает для каждого чанка эмбеддинг локальной моделью `multilingual-e5-small`
(`fastembed`, без внешних API) и складывает всё в SQLite `index.db` вместе с
метаданными: `chunk_id`, `strategy`, `source`, `title`, `section`, `ord`.
Поиск — перебор по косинусу нормализованных векторов. Команда `compare`
сравнивает стратегии по статистике нарезки и по 10 контрольным вопросам.

## Запуск

Rust 1.88 или новее. Команды — из `w5d1/`. Первый `index` скачивает модель
(~480 МБ) в `.fastembed_cache/`, ключи не нужны.

```bash
cargo run --release -- index        # пересоздать индекс (~70 с на M-серии)
cargo run --release -- stats        # статистика чанков по стратегиям
cargo run --release -- search "как работает пауза задачи" --strategy fixed -k 3
cargo run --release -- compare      # статистика + контрольные вопросы
```

`--strategy` по умолчанию `structure`, `-k` — 5. Корень корпуса — папка выше
`w5d1`, другой можно передать через `--root DIR`.

## Корпус

`SOLUTION.md`, `docs/transcript_lektsii_po_ii.md`, `specs/*.md` и `README.md`
всех дней, кроме этого: 24 файла, около 490 КБ русского текста.

## Стратегии

Все размеры — в символах, а не байтах.

- `fixed` — окно до 800 символов с перекрытием ~120; граница сдвигается назад
  к пробелу или переводу строки, чтобы не резать слово. `section` — путь
  заголовков, действующий в начале окна.
- `structure` — разбиение по заголовкам `#`/`##`/`###` (решётки внутри
  ```-блоков не считаются), `section` — путь вида `Глава > Раздел > Пункт`.
  Секции длиннее 1200 символов дорезаются окнами fixed с тем же перекрытием,
  секции короче 150 символов приклеиваются к следующей (или к предыдущей,
  если следующая выше уровнем); метка склеенного чанка перечисляет обе
  секции: `Раздел > A + B`.

Чанк «оборван посреди предложения», если его последний непробельный символ не
из `.!?…:` и разрез пришёлся не на пустую строку и не на конец секции или файла.

## Что показало сравнение

Прогон 2026-09-28, 941 чанк на обе стратегии:

- `fixed` — 463 чанка, длина 178/779/795/799 (min/avg/median/max), обрывов
  86.8%, 230 уникальных секций.
- `structure` — 478 чанков, длина 156/697/791/1198, обрывов 41.6%,
  259 уникальных секций.
- Контрольные вопросы: по файлу обе стратегии попадают одинаково
  (hit@1 8/10, hit@3 10/10), а по файлу и разделу `structure` заметно точнее:
  hit@1 6/10 против 2/10, hit@3 7/10 против 5/10.

Вывод: нужный файл находят обе, но `fixed` чаще достаёт соседний кусок того же
файла — окно режет раздел посередине и склеивает конец одного раздела с
началом другого, поэтому его метка `section` описывает текст хуже. Структурные
чанки начинаются с заголовка, и заголовок сам работает как подсказка для
эмбеддинга. Цена — неравномерная длина: от 156 до 1198 символов.

## Где смотреть код

- `src/chunk.rs` — `chunk_fixed`, `chunk_structure`, пути заголовков, тесты.
- `src/main.rs` — корпус, эмбеддинги с префиксами `passage: `/`query: `,
  SQLite, `search`, `stats`, `compare` и контрольные вопросы.

## Сценарий видео

1. Показать `chunk_structure` и `chunk_fixed`, схему таблицы в `index`.
2. `index` — прогресс и время, затем `stats`.
3. `search` одного вопроса с `--strategy fixed` и `structure`.
4. `compare` — вопросы с top-1 каждой стратегии и итоговая табличка.
