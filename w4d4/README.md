# Исследователь — цепочка MCP-инструментов и шарик «Исследователь»

День 19: агент за один ход собирает отчёт цепочкой MCP-инструментов:
поиск GitHub → обзор DeepSeek → Markdown-файл в `data/reports/`.
Основа — `w4d3`: чат, память, инварианты, этапы и утверждение плана сохранены.
Состояние хода показывает шарик «Исследователь»: клик открывает окно
«Размышление» с рассуждением модели и шагами цепочки.

Один бинарник, два режима:

- `--mcp-server` — MCP по Streamable HTTP на `127.0.0.1:8800/mcp`, планировщик
  и инструменты цепочки в том же процессе. Наружу не публикуется, слушает только localhost.
- без аргументов — веб-интерфейс с агентом на `127.0.0.1:8799`, вход по TOTP.
  К MCP-серверу подключается как клиент по `WATCH_MCP_URL`.

## Инструменты цепочки

- `search_repositories(query, limit)` — поиск GitHub, результат хранится
  в SQLite и возвращает `search_id` и `sha256` снимка.
- `summarize(search_id)` — обзор сохранённого поиска на русском в Markdown
  (5–12 пунктов, только по сохранённым данным), возвращает `summary_id`.
- `save_to_file(summary_id, filename)` — файл `data/reports/<имя>.md`
  со строкой происхождения в шапке
  (`search #<id> sha256:<…> → summary #<id> sha256:<…>`), возвращает
  `file`, `url` (`/api/files/<имя>.md`), `bytes` и `sha256` тела.

Контракт цепочки — по id, не по тексту: `summarize` принимает `search_id`
из результата `search_repositories`, `save_to_file` — `summary_id` из
`summarize`. Имя файла — латиница в нижнем регистре, цифры, `-` и `_`
(`report` и `report.md` дают `report.md`). Ошибка — результат
с `isError: true` и русским текстом, а не пустой успех. Остальные инструменты
(`watch_create`, `watch_list`, `watch_delete`, `watch_summary`) — как в `w4d3`.

Агент делает до 5 вызовов инструментов за ход; `watch_*` после первого
результата цепочки недоступны.

Режим «План» (переключатель у поля ввода, как Plan mode в Claude Code) по
умолчанию выключен: инструменты доступны сразу, этап задачи в запрос и в
проверку не идёт. Включённый «План» возвращает поведение `w4d3`: этапы,
правило этапа «E» в проверке и инструменты только на **Выполнении** после
утверждения плана. Валидатор зовётся, только когда есть что проверять —
включённые инварианты (при включённом слое) или правило этапа.
Скачивание `GET /api/files/{name}` — только с сессией TOTP, как весь `/api/*`.

## Запуск локально

Rust 1.88 или новее. Команды — из папки `w4d4`. Ключи — в корневом `.env`
(шаблон `../.env.example`).

1. Секрет для входа:

   ```bash
   cargo run -- --totp-init
   ```

   Строку `TOTP_SECRET=…` добавить в корневой `.env`, otpauth-ссылку — в приложение-аутентификатор.
2. Терминал 1 — MCP-сервер:

   ```bash
   cargo run -- --mcp-server
   ```

3. Терминал 2 — веб-интерфейс:

   ```bash
   cargo run
   ```

   Открыть `http://127.0.0.1:8799`, ввести код из приложения. Без `TOTP_SECRET`
   веб-режим не стартует. Вход, сессии и кнопка «Выйти» — как в `w4d3`.

## Где смотреть код

- `src/watch.rs` — три инструмента цепочки, `searches`/`summaries`, `report_name`, `REPORTS_DIR`.
- `src/agent.rs` — цикл до 5 вызовов, `tool_traces`, рассуждение хода, строка id, метрики.
- `src/main.rs` — маршрут `GET /api/files/{name}` (`report_response`).
- `static/index.html` — шарик, окно «Размышление», чип файла, пустой чат.

## Проверки

```bash
cargo test
cargo clippy --all-targets -- -D warnings -A clippy::too_many_arguments -A clippy::double_ended_iterator_last
cargo build --release
```

119 тестов прошли. Новые тесты: цепочка `search → summarize → save_to_file`
через MCP с fixture GitHub и fixture DeepSeek (тело запроса равно payload,
`input_sha256` равен `sha256` поиска, тело файла после шапки побайтно равно
тексту сводки, ошибки `search_id`/`summary_id`/ключа/таймаута не пишут в БД);
чистая функция решения раунда (лимит 5, потолок 6 запросов, `watch_*`
недоступны после результата); склейка и усечение рассуждения; мини-роутер
скачивания с входом RFC-кодом (401 без cookie, 400 на неверное имя, 404 на
отсутствующий файл); `report_name` (точки, регистр, повторы имён).

## Деплой

Файлы в `deploy/`: `Caddyfile`, `w4d4-mcp.service`, `w4d4-web.service`
(веб стартует после MCP) и `deploy.sh`. Переключение с `w4d3`:
остановить и отключить `w4d3-mcp`/`w4d3-web`, включить `w4d4-mcp`/`w4d4-web`.
Деплой — вне конвейера, после подтверждения, по `SOLUTION.md` §9.8.

## Известные ограничения

- Цепочка обзора работает только на DeepSeek: `summarize` использует
  `DEEPSEEK_API_KEY` независимо от выбранного в чате провайдера; без ключа
  инструмент отвечает ошибкой «Нет ключа DeepSeek».
- Если ход упал после `save_to_file`, файл на диске остаётся, а шаги
  в чат не попадают: `tool_traces` и рассуждение пишутся в сообщение
  только в конце успешного хода.

## Сценарий видео

1. Показать в `src/watch.rs` три инструмента, передачу id и `sha256`.
2. Войти кодом из приложения-аутентификатора.
3. В новом чате: «Найди три Rust-проекта для полнотекстового поиска, сделай
   обзор и сохрани в файл rust-search-review» — одним сообщением,
   «План» выключен.
4. Шарик меняет состояния («Ищет на GitHub…», «Пишет обзор…»,
   «Сохраняет файл…», «готово»). Клик по шарику — окно «Размышление»:
   три шага, `search_id` из поиска равен аргументу `summarize`.
5. Скачать файл по чипу под ответом, показать строку происхождения в шапке.
6. Перезагрузить страницу: окно с рассуждением и шагами и чип файла на месте.
