# AI Advent Challenge — рабочие правила репозитория

Репозиторий с заданиями челленджа. Вся работа делается через ИИ-ассистента.

## Челлендж

- Задания выдаются по будням в 14:00 МСК.
- Все 5 заданий недели должны быть сданы к понедельнику 14:00 МСК, иначе выбывание.
- Формат сдачи каждого задания: **код + видео**.
- Сдача: комментарий в своём слоте [таблицы](https://docs.google.com/spreadsheets/d/1eFmeejRLXnT5fic3uxagtNgQBvv6uAKUG5McRlEo-eE/edit) со ссылками.
- Проверка заданий выборочная и асинхронная — может прийти просьба переделать.

## Структура

Одна папка на задание: `w<неделя>d<день>` — `w1d1`, `w1d2`, ... `w2d1`.
Каждая папка **самодостаточна**: собирается и запускается отдельно, без общих модулей.

Общий на весь репозиторий только `.env` в корне (ключи) — его находят все дни.

## Язык

Дефолт — **Rust**. Причины: реально новый для автора язык, один статический
бинарник для деплоя на VPS в поздних заданиях, зрелые библиотеки под задачи
челленджа (`reqwest`, `axum`, `teloxide`).

Исключение — **Python** для дней, где нужна ML-экосистема (эмбеддинги,
векторные БД, распознавание речи, обработка данных). Разнобой допустим:
папки дней независимы.

## Провайдеры LLM

Ключи и активный провайдер — в `.env` в корне (шаблон: `.env.example`).
`.env` в `.gitignore`, в репозиторий не попадает.

- **DeepSeek** — провайдер по умолчанию.
- **OpenRouter** — подключается, когда нужна модель другого назначения
  (Claude, GPT, Gemini, специализированные модели). Переключение —
  `LLM_PROVIDER=openrouter` в `.env`.

Оба совместимы с форматом OpenAI Chat Completions: различаются только базовым
URL, названием модели и переменной с ключом. **Anthropic API** (свой формат)
подключаем отдельным клиентом только когда задание реально потребует
качественного tool use.

## Принципы работы

- **Минимальный достаточный код.** Задание просит «минимальный код» —
  значит один файл, а не подсистема. Никакого future-proofing.
- **Общий модуль появляется только на втором реальном call site.** Не выносить
  клиент LLM в общую библиотеку, пока это не понадобилось дважды по-настоящему.
- **Зависимость берётся, когда она сокращает код, а не наращивает систему.**
  Критерий один: с ней кода меньше, чем без неё, и она решает задачу целиком,
  а не наполовину. Своя реализация терминального ввода, HTTP или разбора
  форматов вместо зрелой библиотеки — не минимализм, а лишний код на
  сопровождении. Обратное тоже верно: зависимость ради одной функции,
  которая пишется в десять строк, не берётся.
- **Секреты только в `.env`.** Ни в коде, ни в README, ни в кадре видео.
- Ошибки должны быть читаемыми: понятное сообщение вместо паники.

## Чек-лист сдачи задания

1. Код в папке дня, запускается одной командой.
2. Живой прогон проверен.
3. `README.md` в папке дня: что делает, как запустить.
4. `git push` в публичный репозиторий.
5. Видео: показать код, запуск, ответ модели.
6. Комментарий в своём слоте таблицы со ссылками на репозиторий и видео.
