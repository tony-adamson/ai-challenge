# Исследователь — подключение MCP

День 16: продолжение `w3d5` с тематикой личного исследователя.
Сохранены чат, память, инструкции, инварианты и этапы задачи с утверждением плана.
Добавлен клиент официального Rust SDK `rmcp`, который подключается к публичному
MCP-серверу Exa и получает каталог инструментов. Свой MCP-сервер не нужен.

## Запуск

Требуется Rust 1.88 или новее и доступ в интернет. Первая сборка скачивает зависимости.

Из папки `w4d1`:

```bash
cargo run -- --mcp-tools
```

Команда выводит JSON: адрес, сведения о сервере, имена инструментов,
описания и JSON Schema параметров. LLM-ключи для неё не нужны; `.env` и
локальные данные чата этот режим не читает и не создаёт.
Ошибка подключения завершает команду с ненулевым кодом и сообщением в stderr.

Веб-интерфейс:

```bash
cargo run
```

Открой `http://127.0.0.1:8799` → **Инструменты · Exa MCP** → **Подключить Exa**.
Для запуска чата нужен хотя бы один ключ провайдера в корневом `.env`
(см. `../.env.example`). MCP-подключение не использует эти ключи.
Данные нового дня хранятся в `w4d1/data/`, отдельно от предыдущих дней.

## Что делает код

- `src/mcp.rs`: соединение с `https://mcp.exa.ai/mcp` через Streamable HTTP,
  согласование протокола, `tools/list` со всеми страницами и закрытие соединения.
- `src/main.rs`: режим `--mcp-tools` и `GET /api/mcp/tools` для интерфейса.
- `static/index.html`: состояние запроса, реальный каталог и раскрываемые параметры.

На подключение и получение каталога отведено по 20 секунд, на закрытие — 3 секунды.
В веб-режиме одновременно выполняется один запрос каталога; повторный получает 409.
Ошибка MCP возвращает 502 и видимое сообщение; старый каталог перед попыткой очищается.
Успех означает, что соединение проверено и каталог получен. Затем соединение закрывается.

Список не зашит в код. При живой проверке 21 сентября 2026 года Exa вернул
`web_search_exa` и `web_fetch_exa` (сервер `exa-search-server` 3.2.1,
протокол `2025-11-25`). Состав инструментов может измениться.
Анонимный доступ имеет ограничения частоты запросов.
[Описание сервера Exa](https://github.com/exa-labs/exa-mcp-server).

В этой версии модель **не вызывает** MCP-инструменты: `tools/call` не используется.
Каталог не означает, что поиск выполнен или источники уже прочитаны.

## Проверки

```bash
cargo test
cargo clippy --all-targets -- -D warnings
cargo run -- --mcp-tools
```

Тесты MCP используют локальный HTTP fixture: согласование протокола, две страницы
каталога, сохранение схемы параметров и отказ недоступного сервера.
Остальные тесты проверяют унаследованные механизмы чата, памяти и этапов задачи.
При проверке прошли все 92 теста. Строгий Clippy сообщает о трёх прежних
замечаниях из `w3d5`: два `too_many_arguments` в `agent.rs` и один
`double_ended_iterator_last` в `main.rs`. Они воспроизводятся и в предыдущем дне.
С исключением этих двух классов замечаний Clippy проходит; новый код чист.
Генерацию ответов LLM в этой проверке не запускали.
Живой запрос к Exa выполняется отдельно последней командой.

## Сценарий видео

1. Показать `src/mcp.rs`: SDK, адрес Exa, подключение и запрос каталога.
2. Запустить `cargo run -- --mcp-tools`: показать сведения о сервере и инструменты.
3. Запустить веб-интерфейс, открыть «Инструменты · Exa MCP» и нажать «Подключить Exa».
4. Показать успешный статус, названия и описания; раскрыть параметры инструмента.
5. Объяснить: сервер публичный, своего сервера и API-ключа Exa нет; сегодня получаем
   каталог, вызовы инструментов — следующий шаг.

Для демонстрации ошибки можно временно отключить интернет и повторить подключение:
интерфейс покажет отказ или тайм-аут, после восстановления сети доступен повтор.
Не показывай `.env` в записи.
