# w1d1 — запрос в LLM через API

Минимальный CLI: принимает вопрос аргументом, отправляет его в LLM
через REST API и печатает ответ в консоль.

## Запуск

```bash
cp ../.env.example ../.env   # вписать реальный DEEPSEEK_API_KEY
cargo run -- "Ответь одним предложением: что такое API?"
```

```
API — это набор правил и протоколов, по которым программы общаются
друг с другом, обмениваясь данными и функциями.
```

## Как устроено

`src/main.rs`, ~125 строк:

1. читает `.env` из корня репозитория;
2. по `LLM_PROVIDER` выбирает базовый URL, модель и переменную с ключом;
3. показывает крутилку в stderr и шлёт `POST {base_url}/chat/completions` в формате OpenAI;
4. достаёт `choices[0].message.content` и печатает.

Провайдер по умолчанию — DeepSeek. Переключение на OpenRouter —
`LLM_PROVIDER=openrouter` в `.env`. Модель переопределяется
необязательной переменной `LLM_MODEL`.

## Ошибки

| Ситуация | Поведение |
|----------|-----------|
| Нет аргументов | Подсказка по использованию, код возврата 2 |
| Не задан ключ | `не задан DEEPSEEK_API_KEY: скопируй .env.example в .env и впиши ключ` |
| Неизвестный провайдер | Сообщение со списком допустимых значений |
| Ошибка API | Статус и тело ответа |

Крутилка идёт в `stderr` и только когда вывод — живой терминал, поэтому
`cargo run -- "вопрос" > answer.txt` кладёт в файл чистый ответ модели.
