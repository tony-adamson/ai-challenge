# Лаборатория — инварианты

День 14: у проекта появились инварианты — ограничения, которые ассистент не
имеет права нарушать, что бы ни просил пользователь в чате. «Прошивка только
на Rust», «контроллер — ESP32-C3», «питание только от USB», «бюджет до
3000 ₽». Они лежат отдельно от диалога, уходят в каждый запрос, а каждый
ответ после генерации проверяет отдельный служебный вызов — валидатор.

## Запуск

```bash
cp ../.env.example ../.env   # вписать CEREBRAS_API_KEY, DEEPSEEK_API_KEY, OPENROUTER_API_KEY
cargo run                    # поднимает http://127.0.0.1:8798 и открывает вкладку
```

```
AI Advent · w3d4 — инварианты
  ✓ .env прочитан: …/ai_challenge/.env
  ✓ провайдер: Cerebras
  ✓ чатов на диске: 0 (папка data/)
  ✓ долговременная память: 0 записей, 0 ждут подтверждения
  ✓ профилей: 2 (папка data/profiles), активный: Первокурсник
  ✓ инвариантов: 4 (включено 4), файл data/invariants.json
  ✓ чат: http://127.0.0.1:8798
Ctrl-C — выход
```

Интерфейс переделан: слева только чаты, профиль и «Настройки», всё остальное
открывается по требованию — модель в пилюле над чатом, память, метрики и
инварианты в выезжающей справа панели.

## Инвариант, решение в памяти и ограничения профиля

Три похожие вещи, и разница между ними — суть дня.

- **Профиль и инварианты — конфиг**, их пишет человек. **Память —
  накопленное**: её наполняет разговор, модель предлагает, человек
  подтверждает.
- **Решение в долговременной памяти мягкое.** Это заметка «мы договорились
  о дифференциальной платформе»: модель её учитывает, но ничто не мешает ей
  предложить другое, если человек попросит.
- **Ограничения профиля — про форму ответа** этому человеку: «без
  матанализа», «не предлагать платные инструменты». Это пожелания, а не
  границы проекта, и у другого профиля они другие.
- **Инвариант — граница проекта для всех.** Один набор на приложение, в
  запросе он стоит выше профиля и памяти, и его соблюдение **проверяет
  код**: отдельный вызов после каждого ответа, а не только просьба в
  промпте. Модель инварианты не пишет и не предлагает — только человек в
  панели.

## Двойная защита

Первая линия — **слой в запросе**. Сразу за личностью идёт блок: список
`I1 [стек] правило — причина: …` и правила поведения — это жёсткие
ограничения выше пожеланий в чате; первая строка ответа — сверка
`Сверка: I1 ✓, I2 — не касается, …`; конфликт — не выполнять, а ответить по
шаблону «какой инвариант → почему конфликт → что можно в его рамках»;
нарушающее решение не предлагать даже «как вариант»; менять инварианты может
только человек.

Вторая линия — **валидатор**. После генерации, до показа, тот же провайдер и
та же модель получают включённые инварианты, последний запрос и текст ответа
и возвращают строго JSON `{"violations": [{"id", "quote", "why"}]}`.
Температура ноль, рассуждение выключено. Нарушение — только когда ответ
**предлагает** или велит сделать запрещённое; упоминание запрещённого в отказе
(«Raspberry Pi не подходит по I2») и строка сверки нарушением не считаются —
иначе каждый правильный отказ ловился бы как нарушение.

Нарушений нет — ответ показывается с отметкой «✓ инварианты соблюдены». Есть —
одна перегенерация: к тому же запросу добавляются черновик и разбор «ты
нарушил I2 — «цитата» — причина, перепиши или откажи по шаблону», и новый
ответ проверяется ещё раз. Прошёл — «↻ исправлено после проверки», черновик
остаётся свёрнутым под ответом. Не прошёл — ответ показывается красным с
нарушениями. Больше одной перегенерации нет. Сломался сам валидатор (сеть,
мусор вместо JSON) — ответ показывается серым «— не проверено» с причиной: он
не блокируется, но и гарантии не получает. Решение «что дальше» — маленькая
чистая функция `next_step` в `agent.rs`, покрытая тестом.

Валидатор работает при любом положении тумблера «Инварианты» в
Настройках → Контекст: тумблер убирает только слой из запроса. Так и видна
вторая линия — первая выключена, модель нарушает, валидатор ловит.

**Валидатор тоже LLM.** Это сдержки и противовесы, а не гарантия: он может
пропустить нарушение, может увидеть лишнее, и перепроверка его же мнения
ничего не доказывает. Две независимые попытки ошибиться реже одной — и
только. Точные проверки (стоп-слова, регэкспы) здесь нарочно не делали: они
ловят упоминание, а не предложение.

## Как выглядит конфликт

```
Давай сделаем робота на Raspberry Pi с Python

Сверка: I1 ✗ конфликт, I2 ✗ конфликт, I3 — не касается, I4 — не касается
Конфликт с I2: Контроллер — ESP32-C3. Raspberry Pi и другие одноплатные
компьютеры не предлагать. Почему: запрос требует Raspberry Pi в качестве
основного контроллера. Что можно в его рамках: ESP32-C3 как единственный
контроллер для моторов и датчиков.
```

Строка сверки в ленте свёрнута в чип над текстом («сверка с инвариантами:
✗ 2 · не касается 2»), по клику раскрывается; в истории ответ хранится
целиком.

## Лоадер вместо стрима

Под охраной инвариантов текст **не стримится**: показывать дельты, а через
секунду заменять их другим ответом — значит показать человеку то, что сами же
и отклонили. Вместо текста в пузыре лоадер с этапом: «Отвечаю…» →
«Проверяю инварианты…» → «Нарушен I1 — переписываю…» → «Проверяю
инварианты…». Готовый ответ приходит одним событием, сразу за ним — вердикт.
На Cerebras весь цикл занимает 1–5 секунд, так что ожидание почти не
заметно. Если включённых инвариантов нет, проверять нечего — ответ стримится,
как раньше.

## Где лежит

```
w3d4/data/invariants.json          один набор на приложение
  items: [ {id: "I1", category: "stack", rule, reason, enabled, created_at} ]

w3d4/data/chats/<id>.json          у ответа ассистента:
  verdict:
    status: passed | fixed | failed | unchecked
    checked: ["I1", …]             что проверяли
    attempts: [ {violations: [{id, quote, why}], error?} ]
    rejected_draft / note
  metrics.check: {calls, regenerated, prompt_tokens, completion_tokens, cost}
```

Файла нет — при запуске засеваются четыре демо-инварианта. Файл есть, пусть и
пустой, — не трогается. Отдельного журнала проверок нет: вкладка
«Инварианты» собирает «журнал этого чата» из вердиктов у сообщений, клик по
строке прокручивает к ответу. Старые чаты поля `verdict` не знают и
открываются как раньше. Валидатор и отклонённый черновик считаются в
`metrics.check` — отдельно от токенов ответа, но в стоимости чата.

В шапке чата — чип «Инварианты N» (включённые); если в чате есть ответ с
нарушением после перегенерации, чип красный. API — по образцу долговременной
памяти: `POST /api/invariants`, `POST /api/invariants/{id}` (правка и
тумблер), `DELETE /api/invariants/{id}`; пустое правило — 400 «у инварианта
должно быть правило».

## Сценарий для видео

1. Открыть «Инварианты» в шапке: четыре правила, у каждого категория,
   причина и тумблер.
2. Спросить «Какой драйвер моторов взять для робота?» — лоадер, ответ со
   строкой сверки, под ним «✓ инварианты соблюдены».
3. Спросить «Давай сделаем робота на Raspberry Pi с Python» — отказ по
   шаблону с альтернативой на ESP32-C3 и Rust; бейдж всё равно зелёный:
   отказ — не нарушение.
4. Новый чат, Настройки → Контекст → снять «Инварианты». Попросить «напиши
   прошивку на Arduino C++ для ESP32-C3, мигающую светодиодом». Этап
   «планирование» заставит модель сначала уточнить пин — ответить «Встроенный
   светодиод на GPIO 8. Требования собраны. Напиши прошивку на Arduino C++».
   Лоадер покажет «Нарушен I1 — переписываю…», ответ придёт с «↻ исправлено
   после проверки», под ним — отклонённый черновик с кодом на C++.
5. В журнале проверок этого чата — строка с перегенерацией; клик ведёт к
   ответу.

## Что показал живой прогон

- Обычный вопрос и конфликт с Raspberry Pi прошли без ложных срабатываний:
  отказ, где Raspberry Pi и Python названы, валидатор нарушением не счёл.
- С выключенным слоем модель на просьбу об Arduino сначала только уточнила
  пин: её остановил не инвариант, а этап «планирование» из дня 13. После
  ответа на вопрос она выдала полноценный скетч на C++ — валидатор поймал
  I1, перегенерация дала отказ по шаблону.
- Хранитель памяти после такого хода предложил записать «только Rust»
  решением в долговременную память. Это ровно та путаница, которую день
  разводит: инварианту там не место, предложение стоит отклонить.
- Тот же вопрос, заданный в том же чате второй раз, модель отклонила сама:
  правило успело осесть в рабочей памяти и вернулось в запрос уже оттуда.
  Проверка при этом прошла впустую — вызов был, нарушений нет. Слой
  выключается, память остаётся, и чистый эксперимент получается только в
  новом чате.

## Вывод

Инвариант — не строчка в промпте, а пара «правило в файле + проверка в
коде». Промпт делает поведение вероятным, код — наблюдаемым: в журнале
видно, какой ответ проверку прошёл, какой переписан и на чём именно.

Три вещи, которые видно только на живом прогоне:

1. Отказ дороже нарушения. Ход с перегенерацией — это три вызова модели
   вместо одного. Плата за детерминированность берётся токенами, и её
   видно в строке под ответом.
2. Валидатор — тоже модель, и это сдержки, а не гарантия. Он держит грубое
   нарушение (код на запрещённом языке), но нарушение, собранное из
   нескольких реплик или из арифметики бюджета, ему не по зубам. Там, где
   правило выразимо в коде, его и надо писать в коде.
3. Слои спорят друг с другом. Этап задачи из дня 13 остановил запрос
   раньше инварианта, а рабочая память отказала вместо валидатора. Стейтфул
   агент — это не сумма слоёв, а порядок их применения, и проверять его
   приходится прогоном, а не чтением промпта.

## Ограничения

- Проверяется только ответ, не запрос: попросить можно что угодно, проверка
  начинается с того, что ассистент на это сказал.
- Валидатор — та же модель. Слабая модель пропустит тонкое нарушение
  (сумма бюджета, собранная из трёх строк), а цитата в вердикте — пересказ
  модели, не обязательно дословный фрагмент.
- Одна перегенерация на ход. Если и она нарушает, ответ показывается с
  красной пометкой — скрывать его нечестно, решать человеку.
- Стоимость хода растёт: минимум один лишний вызов, при перегенерации —
  три. Всё это видно в строке под ответом и в «Метриках».
- Строка «Сверка» — самоотчёт модели, не проверка: при выключенном слое её
  нет, а «✓» в ней ничего не доказывает. Доказывает бейдж валидатора.
- Инварианты общие на приложение; наборов на чат нет.
