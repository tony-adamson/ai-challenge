# w1d4 — температура

Один и тот же запрос уходит с `temperature` 0, 0.7 и 1.2, по N повторов на
каждую (по умолчанию 5), все запросы одновременно. Ответы стримятся в
браузер тремя колонками, внизу — сводка. Оценка точности, креативности и
пригодности — на операторе; программа кладёт материал рядом и считает то,
что считается механически.

Задание просит сравнить «разнообразие», а разнообразие невозможно увидеть по
одному ответу на температуру: это разброс между *повторами* одного запроса.
Поэтому здесь не три запроса, а 3 × N.

## Запуск

```bash
cp ../.env.example ../.env   # вписать DEEPSEEK_API_KEY; ANTHROPIC_API_KEY — для второй модели
cargo run                    # поднимает http://127.0.0.1:8788 и открывает вкладку
```

## Модели

Основная — из `LLM_PROVIDER`/`LLM_MODEL`, как в прошлые дни. Вторая —
Anthropic, появляется в переключателе, если в `.env` есть
`ANTHROPIC_API_KEY`. Это отдельный формат API (Messages, не Chat
Completions): свои заголовки, тело и события стрима, поэтому в коде две
ветки разбора.

По умолчанию `claude-sonnet-4-6`, переопределяется `ANTHROPIC_MODEL`.
**Sonnet 5 для этого дня не подходит**: он отклоняет `temperature`,
`top_p` и `top_k` с ошибкой 400, температура на нём не регулируется.
Sonnet 4.6 — последний Sonnet, принимающий температуру, и без поля
`thinking` он не рассуждает — эксперимент такой же чистый, как на DeepSeek.

У Anthropic верхняя граница температуры 1.0, поэтому третья колонка для
него уходит с 1.2 на 1.0 и подписывается «1.2 → 1.0» в интерфейсе и в
отчёте.

## Что считается

| Колонка | Как |
|---|---|
| Верно | ответ содержит эталон как подстроку; без эталона — прочерк |
| Уникальных | сколько дословно разных ответов среди повторов |
| Разнообразие | 1 − среднее попарное пересечение множеств слов (Жаккар): 0% — одни и те же слова, 100% — ни одного общего |
| Длина, время, токены | средние по удачным повторам |

Разнообразие — единственная механическая мера; креативность и точность на
открытых задачах оценивает человек, глядя на карточки.

## Почему выключено встроенное рассуждение

DeepSeek V4 Flash по умолчанию думает перед ответом. Проба перед кодом
показала: с рассуждением при T=0 три повтора дают три разных ответа —
шумит само рассуждение, и температуры за ним не видно. Кроме того, при
малом `max_tokens` рассуждение съедает весь бюджет и ответ приходит пустым.
Поэтому запросы уходят с `"thinking": {"type": "disabled"}`, температура
применяется напрямую к тексту ответа. Та же проба без рассуждения: попарное
пересечение слов 0.46 при T=0 против 0.23 при T=1.2.

На OpenRouter (`LLM_PROVIDER=openrouter`) рассуждение выключается полем
`reasoning.enabled=false`: проверено прямым запросом к `deepseek/deepseek-v4-flash`,
с полем `reasoning_tokens: 0`, без него тот же запрос даёт ~220 токенов рассуждения.

## Пресеты

| Пресет | Зачем |
|---|---|
| Точность: простая арифметика (17 × 23) | модель не ошибается ни при каком T — точность на закрытой задаче от температуры не зависит |
| Точность: задача в два действия (32 ученика, 3/8 мальчики) | без рассуждения модель плавает даже при T=0; при 1.2 появляются ответы вроде «120» |
| Креативность: название и слоган | видно, как при T=0 повторы сходятся к одному названию, а при 1.2 расходятся |
| Формат: строгий JSON | видно, ломает ли высокая температура структуру |

Свой запрос — последний пункт списка; текст любого пресета можно править.

## Результаты и выводы

Прогоны 2026-09-03, по 5 повторов на температуру, DeepSeek V4 Flash и
Claude Sonnet 4.6, встроенное рассуждение выключено у обоих. Полные ответы —
в `REPORT.md`.

### Что показали прогоны

**Разнообразие растёт с температурой — на любой модели и любой задаче.**

При T=0 модель выдаёт самый вероятный вариант, и он повторяется. Страдает не качество
одного ответа, а выбор: низкая температура схлопывает его к штампу.

**T=0 не означает одинаковых ответов.**

**Точность на закрытых задачах от температуры не зависит.**

Там, где модель уверена, распределение острое и шуму не за что зацепиться.
Там, где модель не уверена (задача в два действия без рассуждения), ответ плавает при любом
T, и T=0 оказался худшим. Температура не спасает и не губит точность, она
меняет, как часто выпадает второй по вероятности вариант.

### Для каких задач какая настройка

- **T=0** — извлечение данных, классификация, код по спецификации, ответы с
  известным результатом, всё, что потом сравнивается машиной. Минус: на
  открытых задачах штамп.
- **T=0.7** — тексты, объяснения, диалог. Разнообразие уже есть, связность
  не страдает. Разумный дефолт, если задача не попадает в две крайности.
- **T=1.2** — мозговой штурм, названия, варианты формулировок, всё, где
  нужен набор непохожих ответов на один запрос. На закрытых задачах не даёт
  ничего, кроме шума. У Anthropic верхняя граница 1.0.

**Общий вывод.** Температура регулирует разброс, а не качество. Выбирать
её нужно по тому, сколько разных ответов нужно, а не по тому, насколько
точный.

### Оговорки

- Выборка 5 повторов: различия в один-два ответа — шум.
- Встроенное рассуждение выключено намеренно, иначе температуры не видно
  (см. выше). С рассуждением картина на задачах в два действия будет другой:
  модель считает, а не угадывает.
- Мера разнообразия по словам не видит смысловой близости: «Всё крутится
  вокруг качества» и «Всё вращается вокруг качества» считаются разными.
