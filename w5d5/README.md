# День 25: RAG Studio

Общий веб-чат и Electron-окно помогают спроектировать read-only Claude Code-агента. История, цель, ограничения, источники и результаты проверки сохраняются в `data`. Ответы используют книжный поиск, локальные материалы курса/g-harness и research/DeepWiki MCP.

## Запуск

Из каталога `w5d5`:

```sh
npm ci
npm run build
npm run web
# После завершения веб-сервера через Ctrl+C:
npm run desktop
```

Проверены Node.js 25.8.1, npm 11.14.1 и Python 3.14.5 с SQLite FTS5 (по умолчанию `/opt/homebrew/bin/python3`), существующая база `/Users/admin/MyProjects/books-rag/db/books.sqlite3`. Для предметной проверки нужен установленный и авторизованный Claude Code. Доступность подключения проверяется при использовании; ошибка не означает успешную проверку.

Ключи `CEREBRAS_API_KEY`, `DEEPSEEK_API_KEY`, `OPENROUTER_API_KEY` читаются из корневой `.env` курса. В интерфейсе явно выбери provider/model/temperature/reasoning до первого вопроса. Ключи не сохраняются в чате. Не добавляй `.env`, ключи и локальные данные в Git или приложение.

Desktop читает `/Users/admin/MyProjects/ai_challenge/.env`; `W5D5_ENV_FILE` переопределяет этот путь. По умолчанию оба режима используют `/Users/admin/MyProjects/ai_challenge/w5d5/data`; desktop позволяет задать `W5D5_DATA_ROOT`. Один каталог одновременно обслуживает только один процесс; закрытие окна завершает его сервер и операции. Веб-режим открывает браузер и завершается через Ctrl+C.

Пути источников переопределяются `W5D5_BOOKS_DB`, `W5D5_PYTHON`, `W5D5_COURSE_ROOT`; `W5D5_DOCS_ROOTS` — JSON-массив объектов `path`/`kind` (`harness`, `course`, `custom`). `WATCH_MCP_URL` задаёт research MCP, `DEEPWIKI_MCP_URL` — DeepWiki. `W5D5_CLAUDE_PATH` задаёт executable Claude Code. Python-helper `scripts/search_kb.py` входит в локальную упаковку; книги и исходные репозитории остаются внешними источниками.

## Локальная упаковка macOS

```sh
npm run package
open release/RagStudio-darwin-arm64/RagStudio.app
```

Команда собирает arm64 `.app` в ignored `release`. Подпись, notarization и публикация не выполняются. Приложение использует те же внешние `.env`, источники и каталог данных. Наличие `.app` подтверждает упаковку; работу окна, поиск, отмену и восстановление истории нужно проверить отдельно.

## Проверки и приёмка

```sh
npm run check
npm run eval:live
```

`check` выполняет локальные поведенческие проверки. `eval:live` предназначен для двух длинных сценариев через тот же chat API: живые API/MCP/Claude вызовы требуют настроенных подключений. Драйвер выполняет по 13 пользовательских ходов, перезапускает настоящий store после шестого и проверяет независимые ожидания. Нет доступного MCP/API/Claude — gate остаётся красным. После structural PASS нужна ручная сверка всех ответов с источниками и инструкций с task; затем `npm run eval:live -- --review /absolute/path/to/data/eval-RUN/results.json` фиксирует её, сохраняя остальные gates. Реальные результаты фиксируются в `ACCEPTANCE.md`; сценарий или успешная сборка не доказывают живой PASS.

В интерфейсе открой сохранённый источник и сопоставь цитату с фрагментом/страницей. После раннего ограничения и явной смены цели проверь память задачи; закрой приложение, запусти снова и открой тот же chatId. Проверь отмену активной операции. Собери комплект и запусти предметную проверку: статус «готов» относится только к проверенному комплекту актуальной задачи.
