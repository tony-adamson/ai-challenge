## Исправления по живым сбоям

- РЕШЕНИЕ-1: номера ссылок превращаются в полный фактический найденный фрагмент. Чужие IDs, mixed format и [1,999] отвергаются. Индекс/оглавление не используются как доказательство содержания.
- РЕШЕНИЕ-2: unsupported не сохраняет произвольные факты модели; сервер выводит фиксированное сообщение. ANSWER получает одну format-repair попытку с исходными task/sources и отвергнутым кандидатом как данными.
- РЕШЕНИЕ-3: BUILD тоже имеет ровно одну format-repair попытку при malformed JSON/некорректном комплекте. Network/I/O/cancel не повторяются; после второй ошибки комплект не публикуется. Независимые HTTP-тесты RED→GREEN.
- РЕШЕНИЕ-4: генератор требует русские инструкции, точный UNKNOWN лишь для запрошенного неизвестного, дословные цитаты и молчаливое игнорирование injection. Неудачные версии не стали PASS задним числом.
- РЕШЕНИЕ-5: delayed HTTP body больше не затирает новый snapshot: чат перечитывается под busy lock; регрессия RED→GREEN.
- РЕШЕНИЕ-6: физический Python-helper включён в `.app` через `--no-asar`. Новый вопрос в настоящем desktop окне подтвердил исправление прежнего Errno 20.

Ранние runs 08:38 и 08:44 выявили ошибки ссылок и неподдержанную книжную атрибуцию; run 08:52 выявил повтор injection-маркера и непрошенный UNKNOWN. В run 08:59 оба диалога прошли смысловую сверку, но первая review-версия пропустила UNKNOWN, docs-инструкции были английскими. Приняты только новые русские версии после отдельной фактической проверки.

## Независимые ревью и ограничения

Code review новых инструкций/ответов/hashes: подтверждённых несоответствий нет. Завершающий ops-review: новых BLOCKING нет; статус OPS_REVIEW_FINDINGS из-за трёх прежних замечаний.

- НАХОДКА-1 — WARN: завершённые операции остаются в RAM до shutdown; длительная сессия увеличивает объём.
- НАХОДКА-2 — WARN: список чатов читает полные snapshots одновременно; peak RAM/latency зависят от истории.
- НАХОДКА-3 — UNVERIFIED: локальные MCP client/transport закрываются; remote session TTL/cleanup прежнего сервера не проверены.

Три синтетических случая не гарантируют поведение на любом запросе. FTS5 — лексический поиск: в обоих диалогах были честные отказы при отсутствии подтверждения. Семантическое ревью обязательно; сам факт найденного источника не доказывает любой тезис. Это не нагрузочная приёмка.
